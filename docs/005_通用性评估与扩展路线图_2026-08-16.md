## 一、通用性评估：5-10 个营销/拉新/分佣项目的底座能力

### 1.1 已覆盖的能力矩阵

| 能力 | 说明 | 适用场景 | 覆盖率 |
|------|------|---------|--------|
| **DIRECT 百分比奖励** | 按 eventValue 的百分比给本人(SOLURCE) 或直接上级(PARENT) | 本人收益、直推佣金、一级分销 | ✅ 已实现 |
| **LEVEL 链式水位差** | 按祖先链 rankRate 逐级差额分配 | 团队极差、多级代理、链式佣金 | ✅ 已实现 |
| **平台日封顶** | 当天平台总发放上限 | 企业预算控制 | ✅ 已实现 |
| **单用户日封顶** | 当天单个用户收到上限 | 防刷、防套利 | ✅ 已实现 |
| **预算兜底保护** | 按 eventValue 比例设总预算上限 | 活动预算控制、防配置错误超发 | ✅ 已实现（CAP/WARN/REJECT） |
| **百分比拆分** | 按比例拆分金额（最后一项补差） | 70/30 拆分、多科目分配 | ✅ 已实现 |
| **比较分配** | MAX/MIN/FIRST 多金额比较 | 保底/封顶/取最优 | ✅ 已实现 |
| **等级评估** | 条件驱动的等级晋升 | VIP 等级、代理等级 | ✅ 已实现 |
| **复合条件** | AND/OR/NOT 组合条件树 | 复杂晋升条件 | ✅ 已实现 |
| **流水线编排** | 任意组合阶段 | 灵活的计算链路 | ✅ 已实现 |
| **灰度/A-B 测试** | Hash 加权版本路由 | 规则集灰度发布 | ✅ 已实现（Utils） |
| **配置校验** | joi schema 校验 | 防非法配置 | ✅ 已实现（Validation） |
| **高精度金额** | decimal.js 28 位精度 | 资金安全 | ✅ 已实现 |

## 二、能力缺口与扩展路线图

### 2.1 缺口 1：FIXED 固定金额奖励（高优先级）

**场景**：拉新奖励（拉一人奖 50 元）、人头奖励、固定红包

**当前限制**：引擎只支持百分比奖励（rate 作为百分比），不支持固定金额

**解决方案**（估算 2-3 人日）：
1. `RewardDef` 增加 `type: "FIXED"` 和 `fixedAmount` 字段
2. `distributeByDefs` 增加 FIXED 类型处理
3. `direct-calculator` 增加 `calculateFixed` 函数
4. 更新 `ruleSetConfigSchema` 允许 FIXED 类型
5. 更新测试用例

**示例配置**：
```js
{
  rewardId: "referral_bonus",
  type: "FIXED",
  target: "PARENT",
  fixedAmount: "50",       // 固定金额 50 元
  skipRankZero: false,
}
```

### 2.2 缺口 2：WEEKLY/MONTHLY 封顶（中优先级）

**场景**：活动预算（周/月上限）、运营周期控制

**当前限制**：只支持 PLATFORM_DAILY 和 PER_USER_DAILY 两种封顶范围

**解决方案**（估算 1-2 人日）：
1. `capDefSchema` 增加 `WEEKLY`/`MONTHLY` 选项
2. `applyCaps` 增加周/月维度水位追踪
3. 调用方需提供周/月起始结算数据

### 2.3 缺口 3：活动期加成（中优先级）

**场景**：双十一加佣（活动期间佣金翻倍）、限时奖励

**当前限制**：规则集是静态配置，不支持日期范围的特殊比例

**解决方案**（估算 2-3 人日）：
1. 引入 `CampaignDef` 配置：`{ campaignId, dateRange, multiplier }`
2. `pipelineDef` 增加 `CAMPAIGN` handler
3. 在 DISTRIBUTE 阶段后对奖励金额乘以活动系数

### 2.4 缺口 4：退款/撤销（低优先级，一期不做）

**场景**：订单退款 → 回收已发放佣金

**当前限制**：引擎无"负事件"概念

**解决方案**（估算 3-5 人日）：
1. 引入 `EVENT_TYPE: "REVERSAL"` 事件类型
2. `Distribute` 增加逆向计算逻辑
3. 需要业务层配合：记录原始收益，按比例回收

### 2.5 缺口 5：多币种/多资产类型（低优先级）

**场景**：积分 + 现金 + 优惠券的组合奖励

**当前限制**：引擎只支持单一金额维度

**解决方案**（估算 3-5 人日）：
1. `rewardDef` 增加 `assetType` 字段
2. `Allocate.splitByTargets` 支持多资产类型拆分
3. 需要 DB 层的多资产科目支持
