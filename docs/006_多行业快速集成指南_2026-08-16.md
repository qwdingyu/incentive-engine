## 一、集成总览

引擎提供两条完全解耦的接入路径，覆盖"纯计算"与"DB 落账"两类场景：

| 接入路径 | 适用场景 | 需要 DB | 引擎改动 | 参考实现 |
|---------|---------|--------|---------|---------|
| **A. 纯计算路径** | 在线试算、预览、批量离线计算 | ❌ 不需要 | 0 | `demo/scenarios/01~03` |
| **B. 框架服务路径** | 业务落账、幂等结算、事务管理 | ✅ 需要 | 0 | `demo/scenarios/04` |

两条路径共享同一套引擎纯计算核心，新客户接入 = 配置 + 少量胶水代码。

## 二、Demo 项目快速体验

```bash
cd demo
npm install        # 安装 @usethink/incentive-engine（file: 引用本地包）

npm run demo:ecommerce   # 电商分销佣金（纯计算 + 封顶 + 拆分）
npm run demo:content     # 内容平台创作者激励（等级评估 + 预算兜底 + REJECT）
npm run demo:gaming      # 游戏平台推广激励（条件评估 + 多级奖励 + 单用户封顶）
npm run demo:settle      # 跨境电商完整落账（GenericSettlementService + 幂等三层防护）
npm run demo:all         # 依次运行全部（任一断言失败即中断）
npm run check            # 全部 demo 源码语法检查（node --check）
npm run verify           # check + demo:all，建议 CI 使用
```

Demo 全部**无 DB 依赖**（落账演示使用 `demo/mocks/` 内存 mock Model），开箱即跑。
每个场景末尾带**期望值断言**，可作为引擎的集成冒烟测试。

**目录结构**：

```
demo/
  scenarios/                 # 4 个可运行场景（每个含断言）
  mocks/                     # 内存 mock 基础设施（Model / sequelize / ruleSetService）
  utils/print.js             # 统一输出工具
  shared/ecommerce-rules.js  # 电商规则配置（01 与 04 共享）
```

## 三、行业接入场景详解

### 3.1 电商分销（Demo 1）

**业务模型**：订单支付 → 本人返现 + 一级佣金 + 二级佣金

**规则映射**：

| 业务 | 引擎配置 |
|------|---------|
| 本人自购返现 100% | `{ type: "DIRECT", target: "SOURCE", rate: "100" }` |
| 一级推广员佣金 5% | `{ type: "DIRECT", target: "PARENT", rate: "5" }` |
| 二级推广员佣金（8% → 11% 极差） | `{ type: "LEVEL", accumulateInChain: true }` |
| 平台日总预算上限 | `OVER`（totalBudget="110", onExceed="CAP"） |
| 金额拆分 70% 现金 / 30% 积分 | `SPLIT`（targets=[{LIQUID,70},{POINT,30}]） |

**核心代码**（完整见 `demo/scenarios/01-ecommerce.js`）：

```js
const engine = require("@usethink/incentive-engine");

const pipelineResult = engine.Orchestrate.executePipeline({
  stages: [
    { id: "distribute", handler: "DISTRIBUTE", config: { event, directParent, ancestors, rewardDefs } },
    { id: "over", handler: "OVER", config: { totalBudget: "110", eventValue: event.eventValue, onExceed: "CAP" } },
    { id: "cap", handler: "CAP", config: { capDefs: [{ scope: "PLATFORM_DAILY", limit: "2000" }] } },
    { id: "split", handler: "SPLIT", config: { totalAmount: event.eventValue, targets: [...] } },
  ],
});
```

**输出**：
```
[自购返现] buyer_1001: 1000 元
[一级佣金] promoter_501: 50 元
[二级佣金] promoter_501: 80 元（差率 8%）
[二级佣金] promoter_205: 30 元（差率 3%）
```

### 3.2 内容平台创作者激励（Demo 2）

**业务模型**：创作者按粉丝/播放量分级，按等级分成月收益

**规则映射**：

| 业务 | 引擎配置 |
|------|---------|
| 等级晋升（白银/黄金/钻石） | `rankDefs` + `conditions`（COMPARE / AND 复合条件） |
| 等级评估 | `Evaluate.getHighestQualifiedTier(node, rankDefs)` |
| 按等级比例分成 | `{ type: "DIRECT", target: "SOURCE", rate: tier.rate }` |
| 钻石创作者全站加码 | `OVER`（totalBudget="130"） |

**核心代码**（完整见 `demo/scenarios/02-content-platform.js`）：

```js
// 1. 等级评估
const tier = engine.Evaluate.getHighestQualifiedTier(creator, rankDefs);
// → { rankId: "DIAMOND", metadata: { rate: "20" } }

// 2. 按等级比例发收益
const records = engine.Distribute.distributeByDefs({
  event: { sourceNodeId: "creator_777", eventValue: "50000" },
  rewardDefs: [{ rewardId: "content_yield", type: "DIRECT", target: "SOURCE", rate: tier.metadata.rate }],
});
```

**特点**：等级评估支持**非单调条件**（高等级不要求低等级条件时也能正确晋升），
复合条件树支持 AND/OR/NOT 任意嵌套。

### 3.3 游戏平台推广激励（Demo 3）

**业务模型**：新用户首充 → 返积分 + 多级推广奖励，单用户日封顶

**规则映射**：

| 业务 | 引擎配置 |
|------|---------|
| 首充返 100% 积分 | `{ type: "DIRECT", target: "SOURCE", rate: "100" }` |
| 一级推广奖励 10% | `{ type: "DIRECT", target: "PARENT", rate: "10" }` |
| 二级及以上极差奖励 | `{ type: "LEVEL", accumulateInChain: true }` |
| 单推广员日上限 200 | `applyCaps` + `PER_USER_DAILY` |
| 推广员资格判定 | `evaluateCondition`（AND 复合条件） |

**核心代码**（完整见 `demo/scenarios/03-gaming.js`）：

```js
// 资格判定：≥10 人且 ≥5 活跃
const isElite = engine.Evaluate.evaluateCondition(
  { type: "AND", children: [
    { type: "COMPARE", field: "totalReferrals", operator: "GTE", value: 10 },
    { type: "COMPARE", field: "active30Days", operator: "GTE", value: 5 },
  ] },
  promoter
);

// 封顶裁剪（跨用户独立水位）
const capped = engine.Allocate.applyCaps(records,
  [{ scope: "PER_USER_DAILY", limit: "200" }],
  { platformPaid: "0", memberPaid: new Map() }
);
```

### 3.4 跨境电商完整落账（Demo 4）

**业务模型**：订单支付 → 佣金计算 → 幂等落账（同一订单重复提交不重复发钱）

**这是框架服务路径的完整示范**，展示了 `GenericSettlementService` 的全部职责：

| 职责 | 配置项 | 说明 |
|------|--------|------|
| 业务事件 → 引擎事件 | `buildEvent` | 把订单对象翻译成 `{ sourceNodeId, eventValue }` |
| 直接上级映射 | `buildDirectParent` | 返回 `{ id, rankRate }` 或 null |
| 祖先链映射 | `buildAncestors` | 返回 `[{ id, rankRate }]` 数组 |
| 引擎记录 → DB 记录 | `buildRecord` | 把引擎输出映射为落账行 |
| 幂等键 | `idempotency.buildPreReadWhere` | 事务外预读，命中即跳过 |
| 唯一约束兜底 | `idempotency.buildFallbackWhere` | 并发冲突时读取已落账记录 |
| 错误类注入 | `UniqueConstraintError` | **必填**：注入宿主 sequelize 的错误类 |

**核心代码**（完整见 `demo/scenarios/04-full-settle.js`）：

```js
const service = new GenericSettlementService({
  name: "ecommerce-referral",
  ruleSetCode: "ECOMMERCE_REFERRAL",
  model: MockCommissionModel,      // 换成你的 Sequelize Model
  sequelize: mockSequelize,        // 换成你的 Sequelize 实例
  ruleSetService,                  // 提供 getActiveRuleSet(code) 方法
  buildEvent: (order) => ({ sourceNodeId: order.buyerId, eventValue: order.amount, eventType: "ORDER_PAID" }),
  buildDirectParent: (order) => order.promoter ? { id: order.promoter.id, rankRate: order.promoter.rankRate } : null,
  buildAncestors: (order) => (order.ancestors || []).map((a) => ({ id: a.id, rankRate: a.rankRate })),
  buildRecord: (order, rec) => ({
    order_id: order.orderNo, member_id: rec.nodeId, reward_id: rec.rewardId, amount: rec.amount,
  }),
  idempotency: {
    buildPreReadWhere: (order) => ({ order_id: order.orderNo }),
    buildFallbackWhere: (order) => ({ order_id: order.orderNo }),
  },
});

// 幂等：同一订单重复提交只落账一次
const r1 = await service.settle(order);  // { success: true, idempotent: false }
const r2 = await service.settle(order);  // { success: true, idempotent: true }
```

## 四、如何把 Demo 改造成生产项目

### 4.1 纯计算路径（Demo 1-3 → 生产）

```text
demo/scenarios/01-ecommerce.js     →  src/adapters/customer-xxx-adapter.js
```

1. 把 `rewardDefs`/`rankDefs`/`capDefs` 移入规则集配置（DB 表或配置文件）
2. 用 `engine.Adapters.buildPipelineStages(ruleSet, { event, directParent, ancestors })`
   替代手写 stages（自动处理 config_json 合并）
3. 输出记录直接用于业务展示，或交给你的 Service 落账

### 4.2 框架服务路径（Demo 4 → 生产）

```text
demo/scenarios/04-full-settle.js   →  生产项目 src/services/xxx-settlement.service.js
```

1. 替换 `MockCommissionModel` 为你的真实 Sequelize Model（表需带唯一约束）
2. 替换 `mockSequelize` 为真实 Sequelize 实例
3. 替换 `ruleSetService` 为你项目的规则集查询服务（`getActiveRuleSet(code)`）
4. **注入 `UniqueConstraintError`**：`const { UniqueConstraintError } = require("sequelize")` 传入配置，
   否则引擎无法识别唯一约束冲突（可选 peer 解析不到宿主 node_modules）
5. 校验客户配置：`validateCustomerConfig(config)`
6. 在控制器/路由中调用 `service.settle()` 即可

### 4.3 必做的生产化清单

| # | 事项 | 说明 |
|---|------|------|
| 1 | 落账表加唯一约束 | 如 `UNIQUE(order_id, member_id, reward_id)`，防并发重复 |
| 2 | 事务 + 行锁 | `GenericSettlementService.settle()` 已内置事务；余额变更需自行加行锁 |
| 3 | 金额用 decimal string | 引擎输入输出均为字符串，落库用 `DECIMAL(20,4)` |
| 4 | 配置校验 | 写入 DB 前用 `createRuleSetValidation(Joi)` 校验规则集 |
| 5 | 幂等测试 | 覆盖"同一事件重复提交"与"并发同时提交"两种场景 |
| 6 | 日志 | 传 `logger` 配置项，生产环境接 winston |

## 五、规则集配置速查

### 5.1 rewardDefs（奖励定义）

| 字段 | 类型 | 说明 |
|------|------|------|
| `rewardId` | string | 奖励标识（写入选民记录） |
| `type` | string | `DIRECT` / `LEVEL` / `FIXED` / `CUSTOM` |
| `target` | string | DIRECT/FIXED/CUSTOM 用：`SOURCE`（本人） / `PARENT`（直接上级） |
| `rate` | string | **百分比整数**（10=10%，**不是** 0.1） |
| `fixedAmount` | string | FIXED 用的固定金额（decimal string，必填） |
| `amount` | string | CUSTOM 用的固定金额常量（decimal string） |
| `amountFrom` | string | CUSTOM 动态取数路径（可选）：`eventValue` 或 `event.attrs.<path>`，取数失败回退 `amount` |
| `skipRankZero` | boolean | DIRECT/PARENT 是否跳过最低等级（默认 true） |
| `accumulateInChain` | boolean | LEVEL 是否推进链式水位（默认 false） |

### 5.2 rankDefs（等级定义）

| 字段 | 类型 | 说明 |
|------|------|------|
| `rankId` | string | 等级标识 |
| `levelIndex` | number | 等级序号（0 为最低） |
| `conditions` | array | 条件列表：COMPARE 或 AND/OR/NOT 复合条件树 |
| `metadata.rate` | string | 该等级的百分比整数比例 |

### 5.3 capDefs（封顶定义）

| 字段 | 类型 | 说明 |
|------|------|------|
| `capId` | string | 封顶标识 |
| `scope` | string | `PLATFORM_DAILY` / `PER_USER_DAILY` |
| `limit` | string | 上限（decimal string，0=不限制） |
| `onExceed` | string | 一期仅 `REJECT`（丢弃超出） |

### 5.4 pipelineDef（流水线）

| handler | 阶段作用 | 前置条件 |
|---------|---------|---------|
| `DISTRIBUTE` | 奖励分配（必填，通常第一个） | 无 |
| `OVER` | 总预算兜底（CAP/WARN/REJECT） | 在 DISTRIBUTE 之后 |
| `CAP` | 封顶裁剪 | 在 DISTRIBUTE 之后 |
| `SPLIT` | 金额拆分（独立阶段，需 `totalAmount`） | 无 |

> ⚠️ 引擎 v3.0 起对阶段顺序做防御性校验：`CAP`/`OVER` 在 `DISTRIBUTE` 之前会抛明确错误，避免运行期崩溃与静默失效。

## 六、常见接入问题（FAQ）

### Q1: 我的业务是固定金额奖励（拉一人奖 50 元），支持吗？
引擎 v3.0 仅支持百分比奖励。固定金额（FIXED）列入路线图 P0，
见 `docs/005_通用性评估与扩展路线图_2026-08-16.md` §2.1。临时方案：
在 `buildRecord` 中按比例折算或直接覆盖 `amount`。

### Q2: 我的比例字段存的是小数（0.05），直接用行吗？
**不行**。引擎的 `rate`/`ratio`/`rankRate` 均为**百分比整数**（10=10%）。
传 0.05 会被当成 0.05%，收益几乎为 0。接入前请换算：`小数值 × 100`。

### Q3: 我在 ancestors 里只传了 `attrs: { rankRate }`，没传顶层 `rankRate` 行吗？
v3.0 起引擎支持 `node.attrs.rankRate` 回退（顶层 `rankRate` 优先）。
建议新代码统一用顶层 `rankRate` 字段，`attrs` 回退仅兼容旧数据。

### Q4: 引擎不装 sequelize 能用吗？
可以。`GenericSettlementService` 的 sequelize 是可选 peer，
未安装时 `settle()` 正常执行，唯一约束兜底路径自动跳过。

### Q5: 同一订单并发提交，会重复发钱吗？
不会。`settle()` 事务外预读（快路径）挡住大多数重复；
并发下由 DB 唯一约束拦截，`_handleSettleError` 捕获 UniqueConstraintError 后
回读已落账记录按幂等返回。前提：**落账表必须有唯一约束**，
且**必须注入 `config.UniqueConstraintError`**（否则引擎无法识别该错误类）。

### Q6: 我的事件金额是"分"，引擎怎么处理？
引擎只做计算不解释单位。只要 `eventValue` 与 `rate` 同单位即可；
展示层自行 /100。所有金额必须为 decimal string，禁止浮点。
