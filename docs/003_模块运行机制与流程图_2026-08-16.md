## 二、模块详解

### 2.1 Model — 领域数据模型

**文件**：`src/engine/model/`

纯数据对象（POJO），不包含方法，不依赖外部库。

| 类 | 字段 | 用途 |
|----|------|------|
| `EngineNode` | id, parentId, rankId, attrs, tags | 抽象节点（会员/用户/渠道） |
| `EngineEvent` | sourceNodeId, eventType, eventValue | 激励源事件（订单/交易/注册） |
| `RewardDef` | rewardId, type, target, rate, skipRankZero, accumulateInChain | 奖励定义（DIRECT/LEVEL） |
| `AllocationTarget` | target, ratio | 分配目标（按比例拆分） |
| `RankDef` | rankId, levelIndex, conditions, metadata | 等级定义（含晋升条件） |
| `Condition` | type, field, operator, value, subKey, children | 条件定义（COMPARE/AND/OR/NOT） |

### 2.2 Distribute — 奖励分配器

**文件**：`src/engine/distribute/`

```
distributeByDefs({ event, directParent, ancestors, rewardDefs })
  │
  ├─ DIRECT + target=SOURCE → 本人收益（eventValue × rate）
  ├─ DIRECT + target=PARENT → 直接上级收益（calculateDirect）
  │   └─ calculateDirect: eventValue × rate, 支持 skipRankZero
  └─ LEVEL → 链式水位差（calculateLevelChain）
      └─ 遍历 ancestors, 按 rankRate 水位差分配
         (accumulateInChain: true → 累加链式水位)
```

**关键算法：链式水位差**

```
祖先链: [a1(rankRate=10), a2(rankRate=3), a3(rankRate=1)]
水位差:
  a1: 10% - 0%  = 10% → eventValue × 10%
  a2: 3%  - 10% = -7% → 0（跳过，水位不下降）
  a3: 1%  - 10% = -9% → 0（跳过）
```

### 2.3 Allocate — 封顶/拆分/预算兜底

**文件**：`src/engine/allocate/`

```
applyCaps(records, capDefs, state)
  │
  ├─ 平台日封顶（PLATFORM_DAILY）：裁剪后推进 platformPaid 水位
  └─ 单用户日封顶（PER_USER_DAILY）：裁剪后推进 memberPaid 水位

applyBudgetGuard(records, { totalBudget, eventValue, onExceed })
  │
  ├─ CAP：按比例缩减（保留相对比例关系）→ 默认
  ├─ WARN：写入 context.overBudgetWarnings，不修改金额
  └─ REJECT：抛异常，终止处理

splitByTargets(totalAmount, targets)
  └─ 前 n-1 项按比例计算，最后一项补差

compareAmounts(strategy, amounts)
  ├─ MAX：取最大值
  ├─ MIN：取最小值
  └─ FIRST：取第一个非零值
```

### 2.4 Evaluate — 等级/条件评估

**文件**：`src/engine/evaluate/`

```
evaluateCondition(condition, data)
  │
  ├─ COMPARE：按 field/operator/value 比较 → Decimal
  ├─ AND：全部子条件为 true 则 true
  ├─ OR：任一子条件为 true 则 true
  └─ NOT：对子条件取反

evaluateTier(node, tier)
  └─ V0 无条件通过；优先使用 conditions 通用模式；
     回退到遗留字段模式（minDirectCount/minTeamPerformance 等）

getHighestQualifiedTier(node, tiers)
  └─ 遍历全部等级，保留最后一个满足条件的（非单调等级兼容）
```

### 2.5 Orchestrate — 流水线编排

**文件**：`src/engine/orchestrate/`

```
executePipeline({ stages, context })
  │
  ├─ 初始化 context.capState（如未传入）
  ├─ 按 stages 顺序执行
  │   ├─ DISTRIBUTE → distributeByDefs
  │   ├─ CAP        → applyCaps（共享 context.capState）
  │   ├─ OVER       → applyBudgetGuard（共享 context.overBudgetWarnings）
  │   └─ SPLIT      → splitByTargets
  ├─ 每个阶段输出作为下一阶段输入
  └─ 返回 { results, final, context }
```

### 2.6 Adapters — 适配器

**文件**：`src/adapters/`

```
buildPipelineStages(config, { event, directParent, ancestors })
  ├─ 读取 config.rewardDefs / capDefs / pipelineDef
  ├─ 按 pipelineDef.stages 组装执行阶段
  ├─ 缺省：DISTRIBUTE → CAP
  └─ OVER handler 自动注入 eventValue

customerAdapterTemplate
  └─ 新客户接入引擎的参考实现（≤200 行）
```

### 2.7 Validation — 规则集配置校验

**文件**：`src/validation/`

```
ruleSetConfigSchema.validate(config)
  ├─ rewardDefs：rewardId 唯一性，rate 范围 0~1000
  ├─ rankDefs：rankId 唯一性，levelIndex ≥ 0
  ├─ capDefs：capId 唯一性，limit ≥ 0
  ├─ allocators：targets 至少 1 个
  └─ pipelineDef：stages 至少 1 个
```

### 2.8 Utils — 工具函数

**文件**：`src/utils/`

```
selectVersionByRoutingKey(grayscaleConfig, routingKey)
  ├─ 使用 MD5 hash 分桶
  ├─ 按版本权重分配
  └─ 兜底返回最后一个版本

validateGrayscaleWeights(grayscaleConfig)
  └─ 校验 versions 权重总和为 100
```

## 三、数据流图

### 3.1 一次完整的收益计算流程

```
业务层                             引擎
  │                                │
  ├─ 1. 幂等检查（预读 DB）        │
  ├─ 2. 加载规则集（DB → config）  │
  ├─ 3. 构建事件 + 网络节点        │
  ├─ 4. 调用 buildPipelineStages ──► 组装 stages
  ├─ 5. 调用 executePipeline ────► 执行流水线
  │                                ├─ DISTRIBUTE: 本人+直推+极差
  │                                ├─ OVER: 预算兜底保护
  │                                └─ CAP: 封顶裁剪
  │                                │
  ├─ 6. 接收 final 结果 ◄──────────┤
  ├─ 7. 映射为 DB 记录格式         │
  ├─ 8. 事务落账（create）          │
  └─ 9. 返回结果                   │
```

### 3.2 灰度发布数据流

```
运营后台                        业务层                       引擎
  │                             │                          │
  ├─ 配置灰度版本 ──────────────► 写入 DB                    │
  │                             │                          │
  │                    请求到达时                             │
  │                             ├─ 加载规则集（含灰度配置）  │
  │                             ├─ selectVersionByRoutingKey│
  │                             │   (routingKey=会员ID)     │
  │                             ├─ 选择版本 → config_json  │
  │                             └─ 调用引擎 ◄───────────────┤
```

## 四、状态共享机制

### 4.1 封顶水位（capState）

```
context.capState = {
  platformPaid: "0",          // 平台当天已发放总额
  memberPaid: new Map(),      // 各会员当天已发放额 { memberId: "amount" }
}
```

- 同一批次内多个订单：共享 capState，保证后续订单不会超发
- 跨批次：调用方负责保存/恢复 capState（如 yield-engine.service 的跨批共享）

### 4.2 预算兜底警告（overBudgetWarnings）

```
context.overBudgetWarnings = [
  { totalAmount, budgetLimit, totalBudget, overAmount, eventValue, recordCount }
]
```

- 仅在 WARN 模式下写入
- 调用方可读取告警做日志/监控/告警
