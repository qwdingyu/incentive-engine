## 一、类库定位

**@usethink/incentive-engine** 是一个**领域无关的通用营销激励计算引擎**。它不绑定任何业务场景（不分销/返利/佣金/积分/裂变），只做一件事：

> **把「业务规则配置」翻译成「奖励计算结果」，纯计算，零 DB 依赖。**

### 1.1 核心哲学

| 原则 | 说明 |
|------|------|
| **纯计算** | 引擎不查询数据库、不管理事务、不写任何持久化数据 |
| **领域无关** | 引擎不认识「直推/极差/佣金/茸贝/积分」等业务词汇 |
| **配置驱动** | 所有业务规则通过 `rewardDefs/rankDefs/capDefs/pipelineDef` 配置表达 |
| **零外部依赖** | 唯一依赖是 `decimal.js`（高精度金额计算） |
| **可组合** | 5 个模块（Model/Distribute/Allocate/Evaluate/Orchestrate）可任意组合 |

### 1.2 谁应该使用

- **营销/分销/返佣平台**：电商分销、金融返佣、返利商城、积分裂变、拉新奖励
- **多业务线公司**：多个业务线各自有不同的激励规则，但共用一套计算底座
- **SaaS 服务商**：为不同租户提供可配置的激励方案

## 二、使用范围

### 2.1 引擎能做什么

| 能力 | 描述 | 适用场景 |
|------|------|---------|
| **DIRECT 奖励** | 按百分比给「事件来源节点」或「直接上级」发奖励 | 本人收益、直推佣金、一级分销 |
| **LEVEL 链式差额** | 按祖先链水位差逐级分配（每个祖先只拿"水位差"部分） | 多级分销、团队极差、代理链返佣 |
| **封顶裁剪** | 按平台日封顶/单用户日封顶裁剪金额 | 收益上限、日佣金封顶、防超发 |
| **预算兜底保护** | 按 eventValue 的百分比设总预算上限，超发按比例缩减 | 活动预算控制、防配置错误超发 |
| **百分比拆分** | 按比例拆分金额（最后一项自动补差） | 70/30 拆分、多科目分配 |
| **比较分配** | MAX/MIN/FIRST 多金额比较 | 保底/封顶/取最优 |
| **等级评估** | 按条件列表评估节点等级（COMPARE + AND/OR/NOT） | VIP 等级、代理等级、会员等级 |
| **流水线编排** | 任意组合上述阶段，按顺序执行，共享状态 | 完整的收益/佣金计算链路 |
| **灰度/A-B 测试** | 基于 hash 的加权版本路由 | 规则集灰度发布、A-B 测试 |
| **配置校验** | joi schema 校验规则集配置格式 | 防止非法配置写入 DB |

### 2.2 引擎不做什么

| 不做的 | 理由 |
|--------|------|
| **不查询数据库** | 保持纯计算，接入方负责提供数据 |
| **不管理事务** | 事务由业务 Service 层控制 |
| **不写任何记录** | 计算结果返回给调用方，由调用方决定落什么表 |
| **不管理幂等** | 幂等由业务层（事件键/唯一约束）实现 |
| **不管理团队树** | 团队结构（二叉树/太阳线/单轨）是业务层建模 |
| **不管理用户** | 用户/会员/组织是业务层数据 |
| **不管理定时任务** | 收益计算/释放等定时任务由业务层调度 |

## 三、使用边界

### 3.1 输入边界

引擎期望的输入格式：

```
event:        { sourceNodeId, eventValue, eventType? }
directParent: { id, rankRate? } | null
ancestors:    [{ id, rankRate? }]
rewardDefs:   [{ rewardId, type: "DIRECT"|"LEVEL", rate?, target?, ... }]
rankDefs:     [{ rankId, levelIndex, conditions? }]
capDefs:      [{ capId, scope: "PLATFORM_DAILY"|"PER_USER_DAILY", limit, onExceed? }]
pipelineDef:  { stages: [{ handler, config? }] }
```

### 3.2 输出边界

引擎返回：

```
records: [{ nodeId, rewardId, rewardType, amount, snapshot }]
capState: { platformPaid, memberPaid }
overBudgetWarnings: [{ totalAmount, budgetLimit, ... }]  // 仅在 WARN 模式下
```

### 3.3 金额精度

- 所有金额字段为 `string` 类型（decimal 格式）
- 引擎内部使用 `decimal.js` 高精度计算，28 位精度，四舍五入
- 中间计算保留 4 位小数，最终结果不强制填充尾零
- 比较函数（gte/gt/lt/lte/eq）可直接用于 string 比较

### 3.4 依赖边界

```
生产依赖：decimal.js（仅此一个）
可选依赖：joi（使用 Validation 模块时需安装）
```
